## Ingress, replay and byte identity

`inspect_effect_preflight(session_path, ...)` accepts an existing native session
path. It creates a fresh BQ-05a sidecar in memory with `sample=True`, then calls
`recheck_sidecar` on those exact bytes. BQ-05a independently reopens the session,
admission/audit/journal, directive, local rights, sealed receipt, packet and A06
media under native Windows identity, directory and file locks. Both observations
must agree after all final lock checks. No old cache, caller sidecar, named file,
JSON, GitHub artifact, provider receipt or provenance string is sufficient.

`BQ05bEffectPreflight.v1` exports only closed field labels, finite codes and
digest/ref bindings: journey, directive version/digest, native PULSE source and
current runtime SHA, current A06 asset, journal checkpoint, receipt/packet,
and BQ-05a source/record/sidecar digests. Local `SYNTHETIC_FIXTURE` and
`HUMAN_SUPPLIED` remain `LOCAL_IMPORT`, `provider_attested=false`. Actor/account
values, prompts, paths, credentials and private payloads are never projected.
`account_ref` and similar names occur only as fixed checklist field labels.

Serialization uses sorted ASCII canonical bytes and a SHA-256 content seal.
The seal and sidecar SHA establish byte identity only. Constructors perform
closed structural validation, not authentication. An independent receiver
uses `recheck_preflight` to repeat fresh native inspection, comparing all bytes.
Self-resealed reports cannot bypass replay. Repeated read-only inspection is
byte-identical while owner inputs are unchanged. The existing owner may start
bounded local FFmpeg/FFprobe observation processes; the binder starts no process
itself. Temporary Q4 samples remain outside retained PULSE data. No journal,
media, receipt, sidecar or custody write is retained.

This is a current local observation, not a trusted off-host anti-rollback
witness. Owner-detectable journal damage or checkpoint mismatch holds; a fully
restored coherent historical tree is not independently dated or authenticated.
The exported anti-rollback limit therefore remains `NOT_PROVEN`.

## Next-stage private evidence proposal

`BQ05bPrivateEvidenceChecklist.v1` is a static proposal. Proposed receipt names
are labels, not new enrolled contracts, issuer keys or a live verifier. Each
receipt must be independently authenticated and effect-scoped through the
future private owner. Public source JSON cannot supply that authentication.

| Missing proof | Owner | Required independent evidence |
| --- | --- | --- |
| Broker selection | Human | Explicit choice of architecture, provider/account/model/region and exact permitted operation |
| Issuer enrollment | Private broker | Out-of-band Human enrollment, pinned issuer key/audience/role and revocation epoch |
| Off-host isolation | Private broker | Independent witness of same-SID exclusion, secret custody and deploy/admin/auditor separation |

| Replay reservation | Private broker | Durable atomic nonce/request/semantic-target reservation outside caller SID |
| Budget reservation | Private broker | Atomic pre-call reservation with exact cap, amount, currency and settlement scope |
| Effect receipt | Provider | Authenticated effect receipt bound to original idempotency/reservation/request and returned asset |

The checklist's fixed scope fields require exact journey/directive/version,
source/runtime/media SHA, provider/account/surface/action/target, transaction and
display digests, nonce, request/idempotency key, amount/cap/currency, issued/expiry
TTL, revocation epoch and rights digest. Each future proof must bind the same
request, not merely share a friendly label. Private entitlement additionally
binds Human-selected model and region; selection must never be inferred by this
source component. Future native outcomes are proposed as `VERIFIED` only after
independent authenticated match, `HOLD` on missing/invalid proof, and
`UNKNOWN_EFFECT` after ambiguous dispatch. Ambiguity retains the original
idempotency key and reservation; it is not permission to retry or mint a new
nonce. This component cannot produce any such live verified outcome.

**Next Human selection is required:** choose the independent private broker and
provider/account/model/region, scope, rights basis and spending cap/currency;
then obtain a separate authenticated per-effect grant through that private
owner. The user's source Engineering continuation, a GitHub Issue, a source
